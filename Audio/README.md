# 4th & Fury — audio

Every sound in the game — effects, crowd, music and the stadium announcer — is generated by the
scripts in this folder. The dry vocal performances are included in `takes/`.

## Build

```sh
uv run Audio/make_audio.py                # everything, then verify + manifest (about 3-4 minutes)
uv run Audio/make_audio.py sfx music      # only some parts: sfx | crowd | music | voice
uv run Audio/make_sfx.py football         # football effects and field vocals
uv run Audio/verify_audio.py              # re-measure, re-check, rewrite the manifest
```

Needs [`uv`](https://docs.astral.sh/uv/) (it fetches the pinned `numpy` / `scipy` on first run). Output goes to `FourthAndFury/AudioSource/`:

* `SFX_*.wav`, `AMB_*.wav`, `MUS_*.wav`, `VO_*.wav` — 48 kHz, 16-bit PCM. Effects and voice are
  mono; stingers, ambience and music are stereo.
* `audio_manifest.json` — for every file: name, category, duration, channels, whether it loops,
  measured peak and RMS (dBFS), integrated loudness (LUFS), loop-seam figures, BPM/bars for music,
  and the spoken text for announcer lines.

All randomness is seeded from the file name, dependency versions are pinned, and the 16-bit
dither is seeded too, so a re-run reproduces the same files.

## Voice source

The announcer, quarterback and contact grunts use Qwen3-TTS-12Hz-1.7B-CustomVoice with the
Ryan preset. The saved dry performances in `takes/` are inputs to the standard audio build.
To replace individual performances on Apple Silicon, use an environment with `mlx-audio` and
`soundfile` and run `python Audio/make_takes.py ASSET_NAME`. Run the normal audio build after
replacing takes. See the [model card](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-CustomVoice-bf16).

## How the sounds are built

* **Impacts** are assembled from what collides: the crack of hard plastic shells (a few
  short-lived resonances at 1-5 kHz), the heavily damped thud of a body (80-220 Hz, one or two
  cycles — flesh does not ring like a drum), foam and air, then the players hitting the turf.
  Catches are leather on skin; kicks are a dead thump plus the ball's hollow note.
* **Loops** (`SFX_BallAir`, `SFX_Steps`, `SFX_FuryLoop`, the crowd beds, the chant, the night air
  and the three music loops) are rendered as *one period of a periodic signal*: noise is
  synthesised in the FFT domain, every modulator runs a whole number of cycles, note and reverb
  tails wrap round from the end to the start, and filters / compressors / limiters run in a
  circular form. There is no cross-fade because there is no seam.
* **Carrier footsteps** use six one-shot cleat impacts. Each half-cycle of the running gait triggers one.
* **The crowd** is hundreds of individual synthetic people (glottal source → vowel formants, each
  with their own pitch, vocal-tract size, seat and phrasing) over a quieter wash of far voices and
  air, with per-person hand-clapping and finger whistles for the excited crowd.
* **Music** is sequenced in code: drums, double-tracked Karplus-Strong guitar through a
  distortion-and-cabinet model, bass, a brass section, lead, e-piano. The menu theme's "chorus"
  motif (5-5-1-3) returns in E minor over the riff and, in G major, as the victory fanfare; the
  musical stingers are in G major / E minor too, so they sit with the music.
* **Levels** are set by loudness, not peak, so the set is roughly pre-mixed at unity gain: big
  hits and stingers loudest, UI ticks and footsteps quiet, music at -15 to -16.5 LUFS, crowd
  murmur at -27 LUFS and roar at -19 LUFS, announcer lines all at -16 LUFS. Nothing peaks above
  -1 dBFS.
* **Crowd cross-fade**: `AMB_CrowdLow` and `AMB_CrowdHigh` are uncorrelated (different people,
  different lengths: 14 s and 15 s), so use an equal-power cross-fade.

## Checking it without ears

`verify_audio.py` is the pass/fail gate (format, duration, peak, clipping, DC, head/tail, and
three loop-seam tests: sample step, linear-prediction residual, octave-band continuity).

The tools in `qc/` are how the sounds were inspected and tuned; none is needed to build:

```sh
uv run Audio/qc/spectro.py -o sheet.png FourthAndFury/AudioSource/SFX_Hit_*.wav   # spectrograms
uv run Audio/qc/listen.py FourthAndFury/AudioSource/AMB_Cheer_1.wav               # macOS classifier
uv run Audio/qc/describe.py FourthAndFury/AudioSource/MUS_*.wav                   # CLAP zero-shot
uv run Audio/qc/transcribe.py                                                     # announcer vs script
```

* `listen.py` — Apple's built-in sound classifier (303 everyday-sound labels; needs `swiftc`).
* `describe.py` — LAION-CLAP text/audio matching against descriptions you supply.
* `transcribe.py` — Whisper speech recognition of each announcer line, compared with its script.

### How the crowd was tuned

A crowd made of shaped noise is the usual failure: both listeners above call it "waterfall",
"ocean" or "static", whatever its spectrum. So is a crowd of evenly loud sustained voices
("siren", "engine", "bees"). What both accept as a stadium crowd is short shouted bursts from a
hundred or so distinguishable people with gaps between them, over a much quieter wash — so that
is the recipe, and stationary noise is kept 20 dB down. For each crowd file several random
realisations were rendered and the best-scoring seed frozen in `make_crowd.py` (`SEEDS`).

## Known weak spots

Measured, not heard — these are the ones the machine listeners were least convinced by:

* `AMB_Boo`, `AMB_Ooh_*` — recognisably a crowd reacting, but closer to a groan / "ohh" than to
  a distinct "boo"; applause in the cheers reads as crackle when soloed.
* `AMB_Night`, `SFX_FuryLoop`, `SFX_BallAir` — beds of shaped noise: to a classifier they are
  wind / water / static, which is roughly what they are.
* Brass is synth brass (classifiers hear brass and "keyboard / organ" about equally).
