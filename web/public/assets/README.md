# 4th & Fury web assets: renderer reference

Everything in this folder is generated by `web/tools/build_assets.sh` from the Unreal game's sources (`Art/`,
`FourthAndFury/AudioSource`, `FourthAndFury/Content/Fonts`). Do not hand-edit it; change the tools and re-run them.
Every number below comes from the game's C++ (`FourthAndFury/Source/FourthAndFury/*.cpp`), its material
script (`FourthAndFury/Scripts/import_assets.py`) or the art metadata, and the source is cited next to it.

## 1. Coordinate systems

| Space | Units | Axes | Handedness |
|---|---|---|---|
| **Unreal / game sim** (`FurySim`, `FuryTypes.h`) | cm | **X** goal to goal (+X = right end zone as seen from the TV camera), **Y** sideline to sideline (+Y = the near, TV-camera sideline), **Z** up | left |
| **Blender** (`Art/`, `stadium_meta.json`, `anims.json` notes) | m | Z up. Blender = (X/100, −Y/100, Z/100), so +Y is the **far** side | right |
| **glTF / three.js** (every file here) | m | **Y up**: (x, y, z) = (X/100, **Z**/100, **Y**/100) = Blender (x, z, −y) | right |

* All GLBs were written by Blender's glTF exporter with its default +Y-up conversion. Nodes are in metres, with
  no unit scale on any node. The exception is `stadium.glb`: quantization gave its single node a
  dequantization transform, which must be left in place.
* Unreal → three is a plain axis swap: `three.set(X/100, Z/100, Y/100)`. That swap also absorbs the change of
  handedness, so a three camera at +Z looking toward −Z sees exactly what the Unreal TV camera at +Y sees.
* Field landmarks (FuryTypes.h): yard 0.9144 m; goal lines at x = ±45.72 m; end lines at x = ±54.864 m;
  sidelines at z = ±24.384 m. The **home** side defends the **left (−X)** end zone (`AFuryStadium::Dress`).
* **Yaw.** The sim's `Yaw` is in radians, 0 = +X, increasing toward +Y. In three that facing is
  (cos ψ, 0, sin ψ), so set a character's `rotation.y = π/2 − ψ`. Props and crowd carry a Blender yaw about +Z;
  in three that is simply `rotation.y = yaw`, the same angle about +Y.

## 2. Characters: `characters/{lean,mid,big}.glb`

* Builds per position (`BuildFor`, FuryTypes.h): OL/DL → **big**; QB/RB/LB → **mid**; WR/CB/S/K → **lean**.
  Uniform scale per position (`MakeLook`): OL/DL 1.05, WR/CB 0.98, K 0.95, everyone else 1.0.
* **Facing.** At rest the character faces **+Z**, with its left on +X, up +Y, and the feet on y = 0 at the
  origin (the `root` joint). The rest pose has arms out (hands at x ±0.59 m, y 1.09 m). Standing height is
  1.87 m (helmet top).
* One skinned mesh per file. The exporter splits it into 18 primitives, one per material, and all share one
  `Skeleton` of 46 joints. `Armature` (identity) → `root` → … The mesh node is a child of `Armature`; the
  validator warns about that, and it is harmless. Max 4 influences per vertex (3 on big).
* Attributes: `POSITION, NORMAL, TEXCOORD_0` (= Blender **UVMap**, three `uv`), `TEXCOORD_1` (= **NumberUV**,
  three `uv1`), `JOINTS_0, WEIGHTS_0`. There are no textures and no vertex colours.
* All three builds share an **identical rest skeleton** (checked to 0.0 difference), so one `anims.glb` drives them all.
* Joint hierarchy:
  `root → pelvis → {spine_01 → spine_02 → spine_03 → {neck_01 → head, clavicle_l → upperarm_l → lowerarm_l → hand_l → {fingers_l → index/middle/ring/pinky_1_l → _2_l, thumb_l}, clavicle_r → upperarm_r → lowerarm_r → {ball_tuck_r, hand_r → {ball_hand_r, fingers_r → …, thumb_r}}}, thigh_l → calf_l → foot_l → ball_l, thigh_r → {calf_r → foot_r → ball_r, towel}}`.
  Joint-local axes are Blender's bone axes, with local +Y running along the bone.

**Attaching the football** (`AFuryAthlete::GripWorld`): parent `stadium/football.glb` (long axis = its local
X, laces on its local +Y) to the socket joint with

```js
ball.position.set(0, 0, 0);
ball.quaternion.set(0.5, -0.5, -0.5, 0.5);   // = new THREE.Euler(Math.PI/2, 0, -Math.PI/2, 'ZYX')
```

That rotation puts the ball's long axis on the socket's −Y (the socket's Y axis is the ball's long axis) and the
laces on the socket's +Z, matching the game's `FRotator(0, 90, 0)` and the authoring previews. Ignore joint
scale: the game sets the socket scale to 1. On `ball_hand_r` at Throw frame 10, socket +Y points downfield,
(0, 0.158, 0.987).

**Kit colours** (`Fury::KitFor`, FuryTeams.cpp). Team colours are sRGB hex converted to **linear**
(`FLinearColor(FColor::FromHex)`). `Luma = 0.2126R + 0.7152G + 0.0722B` is taken on the linear values.
White = (0.93, 0.93, 0.93), Black = (0.015, 0.015, 0.018), and `darkPrimary = Luma(primary) < 0.03`.

* **Home:** Jersey = primary; Trim = secondary.
  NumberFill = Luma(primary) > 0.35 ? Black : (Luma(secondary) > 0.3 ? secondary : White).
  NumberEdge = Luma(NumberFill) > 0.3 ? (darkPrimary ? accent : Black) : White.
  Pants = Luma(secondary) > 0.25 ? secondary : White; PantsStripe = primary.
* **Away:** Jersey = White; Trim = primary; NumberFill = darkPrimary ? secondary : primary;
  NumberEdge = darkPrimary ? Black : secondary. If Luma(NumberFill) > 0.5, then NumberFill = Black and NumberEdge = primary.
  Pants = darkPrimary ? primary : (Luma(primary) > 0.3 ? secondary : primary); PantsStripe = White.
* **Both:** Helmet = team.helmet.
  HelmetStripe = Luma(helmet) > 0.5 ? primary : (Luma(secondary) > Luma(helmet) + 0.05 ? secondary : accent).
  Facemask = Luma(helmet) > 0.5 ? primary : (0.7, 0.7, 0.72). Socks = home ? Jersey : primary.
  Shoes = home ? Black : White. Gloves = home ? accent : primary.
* Team table (id, primary, secondary, accent, helmet) is in `Fury::Teams()`; the renderer team can copy it from FuryTeams.cpp.

**Jersey numbers** (M_Athlete, `import_assets.py make_athlete`). Only on the Jersey slot. NumberUV (`uv1`) is
0..1 inside the four number squares (front, back, top of each shoulder cap) and outside 0..1 everywhere else.
`textures/numbers.png` is a 10 × 10 sheet: number *n* sits in column `n % 10`, row `floor(n / 10)`, with row 0
at the **top**. R = digit fill, G = outline ring. Load it with `flipY = false` and `NoColorSpace`, then:

```glsl
float inside = step(0., uv1.x) * step(uv1.x, 1.) * step(0., uv1.y) * step(uv1.y, 1.);
vec2  cell   = vec2(mod(n, 10.), floor(n / 10.));
vec2  m      = texture2D(numbers, (cell + clamp(uv1, 0., 1.)) * 0.1).rg * inside;
color = mix(mix(kitColor, numberEdge, m.g), numberFill, m.r);
```

glTF UVs have v = 0 at the image top, the same as Unreal, so the formula is unchanged.

**Helmet logo.** Each of the two HelmetLogo patches fills UVMap 0..1, with U toward the facemask and V up.
Sample `textures/logo_<team>.webp` with `flipY = false`. The result is `mix(helmetColor, logo.rgb, logo.a)`.

**Fabric.** On slots with a Fabric value, the game blends a tiling normal map, `textures/detail/fabric_n.webp`,
at UVMap × 14 by that weight. It is optional.

**Fury glow** (when a team is in Fury). Emissive = `GlowColor (1, 0.35, 0.05) × 2.4 × fresnel`, with fresnel
exponent 3.6 and base reflectance 0.025, on every slot.

**Big-build arm spread** (`SetLook`/`Apply`). The big build adds 7° to `upperarm_l` and `upperarm_r` about each
bone's local X, after the clip pose. Unreal's mirror flips the sign, so in three it should be
`bone.quaternion.multiply(qX(−7°))`. I have not checked this visually: the arms should move away from the chest.

## 3. Animations: `characters/anims.glb` + `characters/anims.json`

* `anims.glb` contains the `Armature` + 46 joints (no mesh) and **52 animations**, one per clip, named exactly as
  in anims.json: `Idle`, `Run`, `CatchHigh`, … The task brief said 54; the game ships 52.
* Each clip was retargeted from the FBX the game imports (`Art/export/anims/A_*.fbx`) onto the exact rig the
  meshes are skinned to. The exporter checked every joint on every frame against the FBX: worst error 1.2 µm.
* **Binding.** Tracks are named `<joint>.quaternion|position|scale` and bind by joint name. Verified in three.js
  (`web/tools/verify_three.mjs`): all 7176 tracks resolve on lean, mid and big. Use one `AnimationMixer` per
  athlete on the character's `gltf.scene` and pass the clips from `anims.glb` directly.
* **Timing.** 30 fps. Clip *frames* N has N+1 keys (0..N) and duration N/30 s. For loops, key N equals key 0, so
  three's `LoopRepeat` over the full duration matches the game, which wraps at N/30 (`FFuryClip::Sample`).
  Sampling is LINEAR. Event times = frame / 30 (precomputed in `anims.json → event_times_s`).
* **Root motion: none. Every clip is in place.** `root` never moves; only `pelvis` (and `ball_hand_r` in
  PickUp/CelebSpike/CatchHigh/CatchChest/DiveBall) carries translation. Every other joint only rotates.
  The sim moves the athlete. Locomotion playback rate is synced to ground speed
  (FuryAthlete.cpp:300-317): `phase += dt × speed / (stride × scale)`, with stride = clip speed × duration.
  That gives Run 8 m/s × 0.533 s = 4.27 m, Jog 3.0 m, Backpedal 2.67 m and Shuffle 1.49 m; the game falls
  back to 2.7 m and 2.3 m for backpedal and shuffle when a clip has no speed. Several anchor/get-up clips
  move the pelvis relative to the root on purpose. For example, DownBack has the pelvis 0.25 m behind the
  root, and GetUpBack/GetUpFront end with the pelvis back over it.
* **Ball sockets per clip.** `"ball"` = `hand` → `ball_hand_r`, `tuck` → `ball_tuck_r`. `ball_frames` [a, b] is
  when the ball rides in the socket. The game's `release_point` for Throw is measured on the control rig before
  baking and is ~14 cm off the shipped clip. Use the bone itself at the event, as the game does: ball_hand_r at
  Throw frame 10 is (−0.050, 1.882, 0.555) in glTF space, local to the athlete.
* The positions/directions in anims.json's notes are in **Blender rig axes** (−Y forward, +X the athlete's left).
  In the athlete's glTF frame, (x, y, z)_blender → (x, z, −y), and `direction` [dx, dy] → (dx, 0, −dy).
* StanceCenter's ball lies on the ground at glTF (0, 0.085, 0.45) relative to the root, with its long axis along Z.

## 4. Stadium: `stadium/stadium.glb`

* The bowl is one node with 14 primitives, ~252k vertices and 173k triangles. Positions are quantized to 16-bit and normals to 8-bit
  (**KHR_mesh_quantization**). Three's GLTFLoader reads that natively, with no decoder. **Do not reset the node's
  transform**: its scale/translation is the dequantization. Bounds: x ±133.5, y 0..55.0, z ±102.8 m.
* Materials are named after the slot and carry the colours `AFuryStadium::ApplySlotMaterials` sets (linear):

* The game's surfaces are single-sided, except M_Glow (Lamp, Screen*, DownFace), which is two-sided.
* **Ad boards** (M_Ads). TEXCOORD_0 U runs 1.0 per board (0..63 along the wall, left to right as seen from the
  field), and the eight 1024×512 cells of T_Ads repeat: `cell = floor(U) mod 8`. For U ≥ 0 that is exactly
  `fract(U / 8)`, so the embedded material uses **KHR_texture_transform scale (0.125, 1) with REPEAT**. Plain
  GLTFLoader output renders the boards correctly; three maps the transform to `texture.repeat`. The raw UVs are
  untouched, so a custom shader can still use `(mod(floor(u), 8.) + fract(u)) / 8.` on `uv`. The same slot
  also covers the LED ribbons on the upper-deck fascias. 63 wall boards of 6.0375 m, band y 0.18..1.12 m.
* Other UVs on the bowl are world-scale tiling coordinates (outside 0..1). Only the detail/grime maps would use them.

### Lights (`BuildLights`)

There are six spot banks from stadium_meta.json. Positions and targets in glTF metres:

| # | Position | Target |
|---|---|---|
| 0 | (−40.663, 46.847, −56.118) | (−17, 0, 5) |
| 1 | (40.663, 46.847, −56.118) | (17, 0, 5) |
| 2 | (−40.666, 36.994, 66.895) | (−17, 0, −5) |
| 3 | (40.666, 36.994, 66.895) | (17, 0, −5) |
| 4 | (−86.825, 46.822, 0) | (−37, 0, 0) |
| 5 | (86.825, 46.822, 0) | (37, 0, 0) |

* Each bank: 11000 cd, colour (1, 0.97, 0.92), attenuation radius 260 m, inner cone 38°, outer 62° (half-angles),
  source radius 3.5 m. In three: `angle = 62°`, `penumbra ≈ 1 − 38/62`.
* Only **bank 0** casts shadows by default. The lighting quality setting gives 0/1/2/4 shadow-casting banks.
  Volumetric scattering is 1.4 on banks 0-3 and 0.6 on banks 4-5.
* Sky light intensity 1. Exponential height fog: density 0.0045, falloff 0.06, inscatter colour
  (0.035, 0.045, 0.07), base at y = 2 m. These are Unreal fog units, so tune them by eye.
* Sky: an inward sphere of radius 4500 m (the engine sphere scaled 9000), unlit, `textures/night_sky.webp`
  (equirectangular 4096×2048, sRGB) × **0.55**. `scene.background` with `EquirectangularReflectionMapping` and
  `backgroundIntensity = 0.55` is equivalent. The game does not define an azimuth for the seam.

## 5. Field and end zones (M_Field)

The turf is **one plane, 128 m × 64 m, centred at the origin on y = 0** (`Field` = engine Plane × (128, 64)).
`textures/field.webp` (4096×2048, sRGB; 3.1 cm per texel) covers it exactly. The sidelines and end lines are
painted inside it, and a 1.8 m white border plus dark apron lie beyond them.

* **Field UV (glTF/three convention, image v = 0 at the top row):** `u = (x + 64) / 128`, `v_img = (z + 32) / 64`.
  The image's **left** edge is at x = −64 (the home end). Its **top** row is z = −32, the far sideline. Its
  **bottom** row is z = +32, the near/TV sideline, where the yard numbers read upright for the TV camera.
  * With three's default `TextureLoader` (`flipY = true`), `new THREE.PlaneGeometry(128, 64).rotateX(-Math.PI/2)`
    maps this directly, because its uv v = 1 (the image top) ends up at z = −32.
  * If you compute UVs yourself with `flipY = false`, use `v = (z + 32) / 64`.
* `textures/field_lines.png` (4096×2048, linear mask) uses the same mapping: R = white paint.
  The game uses it for roughness only: `roughness = mix(0.93, 0.72, lines)`, specular 0.25.
* **End zones** are composited over the field texture in the shader. Each is 9.144 m deep (|x| from 45.72 to
  54.864) and 48.77 m wide. `endzone_<team>.webp` is 2048×512, sRGB, and the art is squeezed 5.36:1 → 4:1,
  so it is meant to be stretched. Work in metres from midfield, m = (x, z), and let `side` = −1 for the left
  (home) end zone and +1 for the right (away) one. Then:

  ```glsl
  float depth  = (54.86 - abs(m.x)) / 9.14;          // 0 at the end line .. 1 at the goal line
  float across = (m.y * side + 24.385) / 48.77;       // m.y = z
  float inside = step(0.012, depth) * step(depth, 0.972) * step(0.004, across) * step(across, 0.996) * step(0., m.x * side);
  vec3  ez     = texture2D(endzone, vec2(across, depth)).rgb;   // flipY = false: image top = end line
  color = mix(color, ez, inside);
  ```

  * **Image top → the end line, image bottom → the goal line.**
  * **Left end zone:** image left edge (across = 0) at z = +24.385 (near side).
  * **Right end zone:** image left edge at z = −24.385 (far side).
  * Each team name therefore reads left to right, upright, for someone standing on the field facing that end
    zone. The two end zones are 180° rotations of each other.
* **Midfield emblem:** `logo_<home>.webp`, a 13 × 13 m square centred at the origin. `p = (x, z) / 13 + 0.5`,
  sampled with `flipY = false`, so the image top is toward −Z (far side) and the emblem is upright for the TV
  camera. Blend: `mix(color, logo.rgb, logo.a * 0.85)`. It is composited after the end zones.
* Turf finish (optional, the game's look):
  * `color *= mix(0.82, 1.1, grass_m(uv × 9).r)`.
  * Then the tone: `grey = dot(c, (0.3, 0.59, 0.11)); c = mix(grey, c, 0.82) × (0.62, 0.66, 0.62)`.
  * Normal map `detail/grass_n.webp` at uv × 48.

## 6. Crowd

`AFuryStadium::BuildCrowd` instances three meshes. It uses HISM with no shadows and one custom float for the section.

* **`stadium/crowd.bin`** is the game's own seat file, byte-identical. Layout: `int32 count`, then
  `count × float32 (x, y, z, yaw, section)`, little-endian, in **Blender** metres. Yaw is about Blender +Z, and a
  figure at yaw 0 faces Blender −Y. There are 32 840 seats, 16 420 per section. `web/src/game/stadium.ts` reads
  this file and re-runs the seating itself.
* **`stadium/crowd_instances.bin`** has the seating already resolved, **bit-exact with the game's
  `FRandomStream(20261117)`**: 6 % of seats empty, kind roll, yaw jitter ±9°, size 0.92..1.08. That leaves
  **30 787 spectators**: 17 783 crowdA (seated), 8 320 crowdB (standing), 4 684 crowdC (arms up);
  15 408 in SeatA blocks, 15 379 in SeatB. Layout, little-endian:
  * Header, 16 bytes: `"FCRD"`, `uint32 version = 1`, `uint32 count`, `uint32 recordSize = 20`.
  * Each record, 20 bytes:
    * `float32 x, y, z` in glTF metres, standing on the tread.
    * `float32 yaw`: radians about +Y; at 0 the figure faces +Z.
    * `uint8 kind`: 0 crowdA, 1 crowdB, 2 crowdC.
    * `uint8 flags`: bit 0 = section (0 SeatA, 1 SeatB); bit 1 = camera-flash spot (the game's `SeatSample()`,
      every 8th seat; flashes spawn 1.1 m above it).
    * `uint8 scale`: s = 0.92 + 0.16 × b / 255.
    * `uint8 rand`: a 0..255 stand-in for Unreal's `PerInstanceRandom`.

  Build one `InstancedMesh` per kind: `matrix = compose((x, y, z), quatY(yaw), s)`.
* **Crowd meshes** (`crowdA/B/C.glb`). One `Crowd` material. `COLOR_0` (RGBA, normalized uint16) is a mask,
  not a colour: R = shirt, G = skin, B = hair, black = trousers. **A = how much the vertex hops.**
* **M_Crowd** (per instance, `Rand` = instance random 0..1):
  * `pick = fract(Rand × 7.31)`.
  * `team = section ? Away : Home`; `other` is the opposite colour.
  * `neutral = mix((0.75, 0.75, 0.78), (0.07, 0.08, 0.1), step(0.5, fract(Rand × 23.7)))`.
  * `shirt = pick < 0.62 ? team : pick < 0.72 ? other : neutral`, then `× mix(0.7, 1.1, fract(Rand × 91.7))`.
  * `skin = mix((0.75, 0.52, 0.38), (0.2, 0.11, 0.06), fract(Rand × 3.77))`.
  * `hair = mix((0.03, 0.025, 0.02), (0.3, 0.2, 0.1), fract(Rand × 13.1))`; `legs = (0.05, 0.06, 0.09)`.
  * `base = shirt·R + skin·G + hair·B + legs·(1 − sat(R+G+B))`, roughness 0.85.
  * **Hop** (world-position offset, in cm in Unreal):
    * `speed = mix(3, 9, E) × mix(0.8, 1.2, fract(Rand × 5.3))`.
    * `hop = max(0, sin(t × speed + Rand × 2π))`.
    * `keen = step(1 − 0.9E, fract(Rand × 41.3))`.
    * Lift by `A × hop² × mix(2, 26, E) × mix(0.25, 1, keen)` **cm** (divide by 100 for metres), where
      E = `SetExcitement` 0..1, default 0.2.

## 8. Audio: `audio/*.mp3` + `audio/manifest.json`

* 139 clips at 48 kHz, CBR libmp3lame with a LAME gapless header. ffmpeg decodes them back to the exact source
  length (verified). Browsers that honour the header should too; Chrome and Firefox are expected to, but this
  was not tested in a browser.
* Bitrates:
  * music: stereo 160 kbps.
  * ambience and the 11 stereo stingers: stereo 128 kbps.
  * other sfx and announcer: mono 96 kbps.
* `manifest.json → files[]` carries: `name`, `file`, `category` (music | ambience | sfx | voice), `group`,
  **`bus`**, **`loop`**, **`volume`** (the gain the game passes at its usual call site), `volume_notes` (other
  call sites or the formula for continuously driven loops), `duration`, `samples`, `sample_rate`, `channels`,
  `lufs`, the announcer caption `text`, and `bpm`/`bars` for music.
* **Buses** (`UFuryAudio::ChannelFor`): `MUS_*` → music, `VO_*` → announcer, `AMB_*` → ambience,
  `SFX_UI*` → interface, every other `SFX_*` → field. Each bus = master × its options slider.
* Loops: MUS_Menu, MUS_PlaySelect, MUS_Halftime, AMB_CrowdLow, AMB_CrowdHigh, AMB_Chant, AMB_Night,
  SFX_FuryLoop, SFX_BallAir, SFX_Steps (SFX_Steps is never played).
* Mixing rules from FuryAudio.cpp:
  * **Crowd beds.** `level` follows excitement at rate 2.5/s. Low = presence × (0.35 + 0.65 cos(level·π/2)),
    High = presence × 0.9 sin(level·π/2). Use an equal-power cross-fade, because the two beds are uncorrelated.
    AMB_Night stays constant at 0.25.
  * **Announcer.** One line at a time. Urgent lines interrupt; others are dropped while a line plays. Cooldown
    is max(0.6 s, duration). While a line plays, the crowd and music bed duck to 1 − 0.35 × announcerGain:
    down at 4/s, back up at 1.3/s.
  * **Music.** Cross-fades in 0.8 s.
  * **Field loops.** They glide to their target volume at 4/s up and 2.5/s down.
  * **Variants.** `PlayOneOf("SFX_Hit", 4)` picks `SFX_Hit_1..4`, with optional pitch spread.
* If a browser ever returns a longer buffer than `samples`, it ignored the gapless header. For loops, set
  `loopStart = 1105 / sample_rate` and `loopEnd = loopStart + duration`.

## 9. Fonts: `fonts/hud/`

`AFuryHUD::BuildFont` registers ten faces (`EFuryFace`). The HUD draws with the eight **Barlow Condensed**
faces: Medium 500, SemiBold 600, Bold 700, ExtraBold 800, Black 900, BoldItalic 700i, ExtraBoldItalic 800i and
BlackItalic 900i. BlackItalic is the most used, then Bold and SemiBold. **Anton** and **Graduate** are
registered, but no HUD code draws with them; they are included so the faces map 1:1. All are WOFF2, with their
OFL licences (`OFL-*.txt`) and a `fonts.css` (one `@font-face` per face). The HUD layout is authored on a
1920×1080 board, and font size is the em height in board pixels.
